# WebRecorder Framework Adapter Skill

This skill guides the sub-agent in taking code generated by `WebRecorder` and transforming it into the enterprise **Playwright TypeScript POM + TestNG** architecture.

---

## Architecture Overview

Target directory: `typescript-tests/`

| Component | Path | Responsibility |
| :--- | :--- | :--- |
| **Base Page** | `framework/base/BasePage.ts` | Base class for all POMs. Provides `click()`, `fill()`, `hover()`, `selectOption()`, `takeScreenshot()`, and integrates `SelfHealingLocator`. |
| **Base Test** | `framework/base/BaseTest.ts` | Extends `@playwright/test` with TestNG lifecycle hooks (`beforeEach`, `afterEach`), auto-captures failure screenshots, and exports `{ test, expect }`. |
| **Data Provider** | `framework/utils/DataProvider.ts` | Equivalent to TestNG `@DataProvider`. Loads JSON datasets from `fixtures/`. |
| **Self Healing** | `framework/utils/SelfHealingLocator.ts` | Multi-strategy fallback locator healing (strict mode, text, structure, ID/name). |
| **Page Objects** | `pages/<Name>Page.ts` | Extends `BasePage`. Defines static locator keys, and provides high-level action methods. |
| **Test Fixtures** | `fixtures/<Name>Data.json` | Parameterized test input data. |
| **Specs** | `tests/<Name>.spec.ts` | Tests using `BaseTest`, `DataProvider`, and POM methods inside `test.step()`. |

---

## Step-by-Step Migration Procedure

When asked to take WebRecorder code and paste/integrate it into the framework:

### 1. Locate the Generated Code
Inspect the latest generated files from WebRecorder:
- **Raw TypeScript Recording**: `typescript-tests/recordings/<Name>.recorded.ts` (contains captured raw locators and sequential actions)
- **Java Page Object**: `src/main/java/pageobjects/<Name>.java`
- **Java Test**: `src/test/java/recorder/<Name>Test.java`
- **Java Test Data**: `src/test/resources/data/<Name>Data.json`

### 2. Refactor the Page Object (`pages/<Name>Page.ts`)
Ensure the Page Object:
1. Imports `Page` from `@playwright/test` and `BasePage` from `../framework/base/BasePage`.
2. Extends `BasePage`.
3. Keeps the locator constants as `static readonly <LOCATOR_KEY> = '<selector>';`.
4. Adds higher-level action methods calling `this.fill()`, `this.click()`, `this.selectOption()`, etc.
   ```typescript
   import { Page } from '@playwright/test';
   import { BasePage } from '../framework/base/BasePage';

   export class LoginPage extends BasePage {
     static readonly USER_NAME = '#user-name';
     static readonly PASSWORD = '#password';
     static readonly LOGIN_BUTTON = '#login-button';

     constructor(page: Page) {
       super(page);
     }

     async login(user: string, pass: string): Promise<void> {
       await this.fill('USER_NAME', LoginPage.USER_NAME, user);
       await this.fill('PASSWORD', LoginPage.PASSWORD, pass);
       await this.click('LOGIN_BUTTON', LoginPage.LOGIN_BUTTON);
     }
   }
   ```

### 3. Ensure Test Data is in `fixtures/`
Make sure the JSON dataset exists at `typescript-tests/fixtures/<Name>Data.json`.

### 4. Refactor the Test Spec (`tests/<Name>.spec.ts`)
Ensure the spec:
1. Imports `{ test, expect, annotateTest }` from `../framework/base/BaseTest`.
2. Imports the Page Object from `../pages/<Name>Page`.
3. Imports `DataProvider` from `../framework/utils/DataProvider`.
4. Uses `DataProvider.loadJson(...)` to load test data for parameterization (TestNG DataProvider style).
5. Calls `annotateTest({ ... })` with enterprise metadata (Epic, Feature, Story, Severity, Tags, TestCaseId, Jira Issue).
6. Wraps major interaction blocks in `test.step('Step Name', async () => { ... })` for nested Allure step reporting.
7. Adds smart assertions:
   - URL checks: `await pageObj.assertUrl(...)`
   - Element visibility: `await pageObj.assertVisible(...)`
   - Text validation: `await pageObj.assertText(...)`
   - Visual snapshot comparison: `await pageObj.assertVisualSnapshot('<name>.png')`
8. **Automatic Auth Prerequisite Integration**:
   - If the recorded test represents an authenticated/post-login flow (e.g., Dashboard, User Management, Asset Management), automatically import the login page object (e.g., `AssetLoginPage`) and inject a `test.beforeEach` hook:
     ```typescript
     test.beforeEach(async ({ page }) => {
       const loginPage = new AssetLoginPage(page);
       const [credentials] = DataProvider.loadJson<any>('AssetLoginData.json');
       await loginPage.loginWithMicrosoft(
         'https://assetmanagementqa.rishabhsoft.com/',
         credentials?.loginfmt,
         credentials?.passwd
       );
     });
     ```
   - This ensures running the feature spec automatically runs the login test first.

```typescript
import { test, expect, annotateTest } from '../framework/base/BaseTest';
import { LoginPage } from '../pages/LoginPage';
import { DataProvider } from '../framework/utils/DataProvider';

const testData = DataProvider.loadJson<{ userName: string; password: string }>('LoginData.json');

for (const data of testData) {
  test(`testRecordedFlow - Login - ${data.userName}`, async ({ page }) => {
    annotateTest({
      epic: 'Storefront',
      feature: 'User Authentication',
      story: 'Login with valid credentials',
      severity: 'critical',
      tags: ['@smoke', '@regression'],
      testCaseId: 'TC-101',
      issue: 'PROJ-101',
      description: 'Verifies user login and storefront navigation.',
    });

    const loginPage = new LoginPage(page);
    await test.step('Navigate to application', async () => {
      await loginPage.navigate('https://www.saucedemo.com/');
    });

    await test.step(`Login with ${data.userName}`, async () => {
      await loginPage.login(data.userName, data.password);
      await loginPage.verifyLoginSuccess();
    });

    await test.step('Visual regression check of inventory', async () => {
      await loginPage.assertVisualSnapshot('inventory.png');
    });
  });
}
```

### 5. Verify the Test Execution & Reports
Run the test suite using `run-tests.bat`:
```powershell
# In typescript-tests/
.\run-tests.bat
```
To capture or update visual baseline snapshots:
```powershell
# In typescript-tests/
.\update-visual-baselines.bat
```
Confirm:
- Test status is `PASSED`
- Visual snapshots match baselines without exceeding threshold
- Lifecycle hooks (`[TEST START]`, `[TEST PASSED]`) log cleanly
- Results generated in `allure-results/` and `reports/html-report/`
- Allure dashboard can be generated/opened with `.\generate-allure-report.bat`
